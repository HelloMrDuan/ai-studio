# 小段映画工作台

面向 AI 漫剧、剧情短片和故事视频生产的一体化创作工作台。

目标不是“一句话随机出片”，而是把故事生产做成可编辑、可确认、可追踪、可局部重做的专业生产链，在保证人物、场景、道具和镜头连续性的同时，减少重复推理、重复生成和 GPU 切换。

## 完整生产链

```text
故事输入
  ↓
① 剧本：故事生产圣经
  ↓
② 角色：角色资产 + 形象版本 + 身份参考
  ↓
③ 视觉：视觉圣经 + 地点资产 + 道具资产
  ↓
④ 分镜：正式镜头合同 + 连续镜头链
  ↓
⑤ 制作：一致性参考 → 快速画面候选 → 高质量精修 → 视频
  ↓
⑥ 成片：配音 + 字幕 + 背景音乐 + 最终合成
  ↓
最终 MP4
```

原工作台的六阶段页面、逐阶段修改、候选预览、丢弃和人工采用交互全部保留。生成成功不等于正式结果，只有用户明确采用的版本才进入下游生产。

## 前半段：一次理解，多次消费

### ① 故事生产圣经

作品前期建立统一事实源，沉淀：

- 不可篡改故事事实
- 世界观与时间线
- 剧情节点与因果关系
- 角色实体与人物关系
- 地点实体与关键道具
- 对白、旁白和连续性事件
- 创作节奏、冲突和高潮策略

后续角色、视觉和分镜阶段不再反复重新理解完整故事，而是读取各自需要的生产上下文切片。

### ② 角色资产与形象版本

角色是项目级版本资产，不只是文本描述：

- 稳定脸部身份
- 发型、体型、肤色
- 常态服装、鞋履、固定配饰
- 主辅配色和身份锚点
- 镜头中允许变化的临时状态
- 多个剧情形象版本
- 每个形象版本的变化原因和生效剧情节点

例如：

```text
少年
├─ 默认造型
├─ 雪山造型
├─ 战斗破损造型
└─ 结局造型
```

修改某个角色或某个形象版本，只让真正引用它的镜头和媒体结果过期。

### ③ 视觉资产

视觉阶段独立维护：

- 项目视觉圣经
- 地点空间结构和固定锚点
- 道具轮廓、材质、结构、颜色和纹样
- 天气、时段、破损等可变化状态
- 地点和道具参考图生成要求

剧情“场次”只负责组织故事，不重复创建一套地点身份。

### ④ 正式分镜合同

每个正式镜头包含可直接生产的信息：

- 剧情节点和时长
- 角色及形象版本
- 地点和道具版本
- 景别、构图、机位、运镜
- 人物动作、表演、视线
- 环境、时间、天气、光线
- 对白、旁白、音效和音乐意图
- 静态代表状态
- 视频起始状态和结束状态
- 图片生成要求
- 视频生成要求
- 连续镜头继承关系
- 智能质量等级

同一地点、同一人物集合、同一形象版本且没有时间跳跃时，后一镜头可继承前一镜头的结束状态；场景切换、时间跳跃、人物变化或形象变化会自动断开连续链。

## 一致性参考资产

用户可以上传参考图，也可以完全不上传。

默认流程：

```text
正式角色 / 地点 / 道具设定
  ↓
自动批量生成缺失参考候选
  ↓
预览 / 修改要求 / 重新生成
  ↓
人工采用
  ↓
成为正式一致性参考资产
```

只有已采用参考资产才允许进入正式镜头画面生产。

当前本地 FaceID 配置为单参考输入，因此单主体身份链已经有明确约束；多角色同镜头仍属于正式发布前需要继续验证和升级的能力边界。

## 智能质量生产

镜头内部按内容价值分为 A / B / C 三档：

- **A**：主角身份、关键情绪特写、高潮、核心场景和核心道具
- **B**：常规剧情镜头
- **C**：过渡、建立、无人物或低风险环境镜头

用户页面只看到“智能质量”，系统负责决定实际生成预算。

图片采用两段式候选：

```text
正式镜头合同
  ↓
快速预览候选
  ↓
用户判断构图和内容
  ├─ 丢弃 / 重做
  └─ 同种子高质量精修
          ↓
      精修候选
          ↓
      用户最终采用
```

精修是独立候选，不会后台偷偷覆盖预览结果。当前 FaceID 工作流使用同一随机种子、同一提示词和同一正式参考资产提高生成预算；在没有独立二次图生图输入的情况下，不宣称像素级锁死原构图。

## 图片与视频生产

正式图片生成参数已经进入冻结 Generation Contract，包括：

- 实际宽高与画幅
- steps
- CFG
- seed
- sampler
- scheduler
- 正式参考资产版本

视频必须从已采用首帧继续生成：

```text
已采用镜头画面
  ↓
正式首帧血缘
  ↓
H3 视频候选
  ↓
预览 / 丢弃 / 采用
```

视频不会绕过正式首帧重新猜开场画面。

## 内容哈希与增量复用

### 文本生产缓存

文本模型调用按照模型、专业 Skill、生产上下文、用户修改和执行目标计算内容签名。输入完全一致时直接复用已有结果，不重复调用模型。

### 媒体生产缓存

图片和视频除了 Temporal 单任务幂等外，还维护跨新任务的项目级媒体内容签名。

图片签名包含：

```text
Prompt
+ 正式参考文件校验值
+ Provider / Workflow 指纹
+ 宽高 / steps / CFG
+ seed / sampler / scheduler
+ 质量阶段
```

视频签名包含：

```text
视频 Prompt
+ 已采用首尾帧文件校验值
+ H3 运行配置
+ 宽高 / 长度 / steps / seed
```

签名完全相同且原媒体文件校验仍有效时，新任务直接复用已有不可变媒体文件，不重新提交昂贵生成任务，也不需要先切换 GPU 工作区。随机 seed 请求不会错误命中跨任务缓存。

## GPU 工作区策略

重型 GPU 服务互斥运行，但工作区不会在每个任务结束后自动关闭。同一类型连续任务继续复用当前已预热工作区。

生产顺序按资源类型组织：

```text
文本模型工作区
故事 → 角色 → 视觉 → 全部分镜和媒体要求

        ↓

图片工作区
批量缺失参考资产 → 镜头图片候选 → 精修候选

        ↓

视频工作区
已采用首帧 → 视频候选

        ↓

人物处理工作区
仅在确实需要人物处理时进入
```

命中媒体内容缓存时会在申请 GPU 工作区之前直接返回，避免为了读取旧结果发生无意义的模型切换。

## 确定性审计优先

能由规则准确判断的问题不额外调用大模型，例如：

- 必填字段是否齐全
- 角色 / 地点 / 道具是否绑定正式版本
- 静态代表状态与图片要求是否闭合
- 视频是否存在已采用首帧
- 资源文件是否真实存在
- 版本依赖是否过期
- 连续镜头是否满足继承条件

只有规则无法判断的语义质量问题才进入更昂贵的语义审计。

## 后期并行生产

④正式分镜确认后，不需要等所有视频完成才开始后期准备。

```text
                         ┌─ 配音预生成 ─→ 字幕预生成
④正式分镜确认 ──────────┼─ 背景音乐意图 / 曲库候选准备
                         └─ ⑤参考图 / 图片 / 视频生产

所有正式视频采用后
        ↓
配音 + 字幕 + 已采用背景音乐 + 视频
        ↓
最终合成
```

背景音乐不会随机乱配：系统只把已经存在的、可验证的用户曲库或默认曲作为候选，用户试听后采用；没有可用音乐来源时会明确提示上传或配置来源。

⑥成片继续支持：

- 旁白编辑
- 配音生成 / 重新生成 / 试听
- 字幕生成 / 编辑 / 保存
- 背景音乐候选试听 / 采用 / 上传替换
- 已采用视频选择
- 最终合成

最终成片重新注册到作品资产图，保留镜头、视频、配音、字幕和背景音乐之间的生产血缘。

## 局部修改与依赖失效

平台维护真实资产版本和父子依赖关系。

例如只修改“少年”的服装：

```text
少年角色资产 v3 → v4
  ↓
少年参考资产过期
  ↓
引用少年的镜头过期
  ↓
对应图片 / 视频过期
  ↓
依赖这些镜头的最终成片过期
```

无关角色、地点和镜头继续有效。单个分镜也能独立保存新版本，只重做该镜头及真实下游。

## 工作台原则

1. **正式资产优先**：模型不得偷偷重写已确认人物、地点和道具身份。
2. **候选不等于正式结果**：所有关键媒体必须显式采用。
3. **局部修改只重算真实下游**：不做无意义的整项目重跑。
4. **视频首帧必须有来源**：只从已采用画面继续生成。
5. **缓存必须可证明一致**：Prompt、参考文件、模型工作流或参数任一变化都会产生新签名。
6. **失败显式暴露**：缺能力、缺资产、合同不完整时不静默换链路。
7. **用户可见内容中文化**：内部稳定技术 ID 不直接当页面文案展示。
8. **测试与正式实现一致**：不维护只为测试通过的伪生产方案。

## 部署

默认目录：

```text
/root/autodl-tmp/ai-studio/platform-v2
```

安装：

```bash
cd /root/autodl-tmp/ai-studio/platform-v2
chmod +x scripts/*.sh
bash scripts/install.sh
```

启动：

```bash
bash scripts/start.sh
```

停止：

```bash
bash scripts/stop.sh
```

检查：

```bash
bash scripts/check.sh
```

AutoDL 对外映射 `6008` 即可。

## 发布前最终验证

代码层已经建立：专业前半段生产 Skill、生产上下文切片、角色形象版本、角色/地点/道具版本资产、连续镜头继承、智能质量、两段式图片候选、文本与媒体内容哈希复用、参考图优先、视频首帧血缘、配音/字幕/背景音乐并行准备和最终合成。

正式发布前仍以真实浏览器和真实媒体质量做最后验收，重点包括：

- 当前作品多镜头人物身份的肉眼一致性
- 多角色同镜头参考能力升级
- 长故事分批生产的剧情和分镜质量
- A/B/C 智能质量在真实 GPU 上的耗时与质量收益
- 从故事输入到最终 MP4 的浏览器完整回归

项目不把“接口成功”或“CI 通过”当成“视频质量已经优秀”；最终标准是实际生成出的连续、可看、可编辑、可稳定复现的视频成片。
