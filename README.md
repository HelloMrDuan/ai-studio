# 小段映画工作台

面向 AI 漫剧、剧情短片和故事视频生产的一体化创作工作台。

目标不是“输入一句话直接抽卡出片”，而是把故事生产拆成可编辑、可确认、可追踪、可局部重做的专业流程，在保证人物、场景、道具和镜头连续性的同时，尽量减少重复推理、重复生成和 GPU 切换成本。

## 产品定位

小段映画工作台提供完整的故事到成片链路：

```text
故事输入
  ↓
① 剧本：故事生产圣经
  ↓
② 角色：角色资产与形象版本
  ↓
③ 视觉：视觉圣经、地点资产、道具资产
  ↓
④ 分镜：正式镜头合同
  ↓
⑤ 制作：参考图 → 镜头画面 → 视频
  ↓
⑥ 成片：配音 → 字幕 → BGM → 合成
  ↓
最终 MP4
```

每个阶段都保留人工修改、重新生成和显式采用能力。候选结果不会因为“生成成功”就自动覆盖正式资产。

## 核心能力

### 1. 故事生产圣经

作品只在前期做一次完整故事理解，把后续需要反复使用的事实沉淀为统一生产上下文：

- 不可篡改故事事实
- 世界观与时间线
- 剧情节点与因果关系
- 角色实体与人物关系
- 地点实体
- 关键道具
- 对白与旁白事实
- 连续性事件
- 创作节奏与高潮策略

后续专业阶段只读取自己需要的上下文切片，不再反复把整篇故事和全部历史对话重新交给模型解释。

### 2. 角色资产与形象版本

角色不再只是一个文本描述，而是项目级可复用资产：

- 稳定身份
- 脸部、发型、体型、肤色
- 常态服装、鞋履、固定配饰
- 主辅配色
- 固定身份锚点
- 可变化镜头状态
- 多个剧情形象版本
- 每个版本的变化原因和生效节点
- 角色身份参考图生成要求

例如同一个角色可以拥有：

```text
默认造型
雪山造型
战斗破损造型
结局造型
```

分镜绑定“角色 ID + 形象版本”，避免整部作品从头到尾只依赖一张模糊角色描述。

### 3. 视觉资产

视觉阶段把项目美术方向和可复用实体分开管理：

- 项目视觉圣经
- 地点空间结构
- 固定场景锚点
- 道具轮廓、材质、结构和纹样
- 天气、时段、破损等可变化状态
- 地点/道具参考图生成要求

“场次”只负责组织剧情，同一个地点跨多个场次仍然维护同一套地点身份。

### 4. 正式分镜合同

每个镜头必须具备可直接进入生产的结构化信息：

- shot_id / 剧情节点 / 时长
- 角色和形象版本
- 地点和道具版本
- 景别、构图、机位、运镜
- 人物动作、表演和视线
- 环境、时间、天气和光线
- 对白、旁白、音效、音乐意图
- representative_state
- video_start_state / video_end_state
- image_prompt
- video_prompt
- continuity_link
- 智能质量等级

相邻镜头属于同一人物、同一地点、连续时间和连续动作时，可以继承上一镜头结束状态；场景切换、时间跳跃、人物集合变化或形象版本变化时会显式断链。

### 5. 一致性参考资产

用户可以上传参考图，也可以完全不上传。

默认流程：

```text
角色 / 地点 / 道具正式设定
  ↓
自动生成一致性参考候选
  ↓
预览
  ↓
修改生成要求 / 重新生成
  ↓
人工采用
  ↓
成为正式参考资产
```

只有已采用的参考资产才允许进入正式镜头生产。

### 6. 图片与视频候选

镜头生产继续采用候选制：

```text
正式镜头合同
+ 正式参考资产
  ↓
图片候选
  ↓
预览 / 重做 / 采用
  ↓
已采用图片作为视频首帧
  ↓
视频候选
  ↓
预览 / 重做 / 采用
```

视频不会绕过已采用首帧重新“猜一张开场画面”。

### 7. 局部修改与依赖失效

平台维护资产版本和真实依赖关系。

例如只修改“少年”的服装：

```text
少年角色资产 v3 → v4
  ↓
少年参考图过期
  ↓
引用少年的镜头过期
  ↓
对应图片 / 视频过期
  ↓
依赖这些镜头的最终成片过期
```

无关角色、场景和镜头保持有效，不进行全项目重算。

单个分镜也可以独立保存新版本，只重新制作该镜头及真实下游。

## 质量与速度策略

### 一次理解，多次消费

完整故事只在故事生产阶段建立权威事实源。角色、视觉、分镜分别消费经过裁剪的生产上下文，从源头降低重复 Token、重复理解和内容漂移。

### 内容哈希缓存

模型调用按以下内容计算稳定签名：

```text
模型身份
+ 当前专业 Skill
+ 当前生产上下文版本
+ 当前用户修改
+ 当前执行目标
```

输入完全一致时直接复用已经生成的结果，不重复调用模型。

媒体任务继续使用幂等任务 ID、持久 Prompt ID 和资源版本，工作进程重试不会无条件重复提交昂贵的图片/视频任务。

### GPU 工作区分组

重型运行时按生产阶段组织，避免在单个镜头之间反复切换：

```text
Qwen 常驻阶段
故事 → 角色 → 视觉 → 全部分镜与媒体提示词

        ↓

图片工作区
全部缺失参考资产 → 待制作镜头图片候选

        ↓

视频工作区
已采用首帧 → 视频候选

        ↓

人物处理工作区（仅需要时进入）
```

文本、图片、视频和 CPU/IO 后处理使用独立任务类别，调度层可以分别控制并发和资源占用。

### 智能质量等级

镜头按内容价值分为三个内部等级：

- **A**：主角身份、关键情绪特写、高潮、核心场景和核心道具
- **B**：常规剧情镜头
- **C**：过渡、建立、无人物或低风险环境镜头

系统根据等级选择候选成本、正式精修成本和审计强度。用户不需要手工维护模型参数，只需要使用“智能质量”。

### 确定性审计优先

能用规则准确判断的内容不额外调用大模型，例如：

- 必填字段是否齐全
- 角色 / 地点 / 道具是否绑定正式版本
- representative_state 与图片要求是否闭合
- 视频是否存在已采用首帧
- 资源文件是否真实存在
- 版本依赖是否已过期

只有确定性规则无法判断的语义质量问题才进入更昂贵的语义审计。

## 成片后期

⑥成片支持：

- 旁白编辑
- TTS 生成 / 重新生成 / 试听
- 字幕生成 / 编辑 / 保存
- BGM 上传和替换
- 已采用视频选择
- FFmpeg 最终合成

最终成片会重新注册到作品资产图中，保留视频、配音、字幕、BGM 和来源镜头之间的血缘关系。

## 工作台原则

1. **正式资产优先**：生成模型不得覆盖已确认角色、地点和道具身份。
2. **候选不等于正式结果**：必须显式采用。
3. **上游修改只影响真实下游**：不做无意义的整项目重跑。
4. **视频首帧有来源**：视频必须从已采用画面继续生成。
5. **失败显式暴露**：缺能力、缺资产、合同不完整时不静默降级成另一条链路。
6. **用户可见内容中文化**：内部技术 ID 可以稳定存在，但页面不直接暴露内部状态码。
7. **测试和正式实现一致**：不维护一套只用于测试的媒体生产方案。

## 主要运行组件

```text
6008  小段映画工作台
6006  本地文本模型服务
8188  图片 / 视频生成内部接口
7233  Temporal
```

重型 GPU 工作区互斥运行，由统一 GPU 调度器负责排空、停止、释放显存、启动、预热和健康检查。

## 部署

默认目录：

```text
/root/autodl-tmp/ai-studio/platform-v2
```

安装：

```bash
cd /root/autodl-tmp/ai-studio/platform-v2
chmod +x scripts/*.sh
bash scripts/install.sh
```

启动：

```bash
bash scripts/start.sh
```

停止：

```bash
bash scripts/stop.sh
```

检查：

```bash
bash scripts/check.sh
```

AutoDL 对外映射 `6008` 即可。

## 更新当前开发分支

```bash
cd /root/autodl-tmp/ai-studio/platform-v2
git pull --ff-only origin refactor/xiaoduan-studio-v3
bash scripts/stop.sh
bash scripts/start.sh
```

浏览器更新后建议执行一次强制刷新。

## 当前生产验证重点

当前版本已经具备完整的版本资产、候选采用、真实图片物化、视频首帧血缘、TTS、字幕、BGM 和最终合成链路。

正式发布前继续重点验证：

- 多镜头人物身份视觉一致性
- 多角色同镜头参考能力
- 长故事分批分镜质量
- 智能质量等级的真实耗时 / 质量收益
- GPU 工作区批调度下的端到端耗时
- 浏览器从故事输入到最终 MP4 的完整回归

项目不把“接口成功”当成“视频质量合格”；最终验收以真实浏览器流程、真实媒体产物和可见内容质量为准。
