# V2.39.6.3 llama.cpp 16K Context Startup Recommendation

## Current configuration

`scripts/start_llm.sh` currently resolves:

```bash
CTX_SIZE=$(get_env GEMMA_CTX_SIZE 8192)
```

and passes the resolved value to llama-server as:

```bash
--ctx-size "$CTX_SIZE"
```

The performance installer does not modify this script or `.env`.

## Recommended AutoDL setting

Set the runtime environment value to:

```bash
GEMMA_CTX_SIZE=16384
```

After restarting the LLM workspace, verify the effective llama-server command contains:

```bash
--ctx-size 16384
```

## Validation sequence

1. Stop the platform and Qwen workspace only when no active task exists.
2. Apply `GEMMA_CTX_SIZE=16384` in the existing AutoDL runtime environment configuration.
3. Start Qwen and verify READY, resolved model `qwen3-32b` and the effective `--ctx-size 16384` argument.
4. Confirm KV-cache allocation fits available VRAM without model offload or startup instability.
5. Start the platform and run the real Stage04 verifier separately.

The Stage04 6,500-token audit guard remains mandatory after this change. The 16K context is safety headroom; it does not replace payload compaction or permit duplicated evidence text to return.
