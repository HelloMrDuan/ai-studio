# 小段映画工作台

面向 AI 漫剧、剧情短片和故事视频生产的一体化创作工作台。

目标不是“一句话随机出片”，而是把故事生产做成可编辑、可确认、可追踪、可局部重做的专业生产链，在保证人物、场景、道具和镜头连续性的同时，减少重复推理、重复生成和 GPU 切换。

## 完整生产链

```text
故事输入
  ↓
① 剧本：故事生产圣经
  ↓
② 角色：角色资产 + 形象版本 + 身份参考
  ↓
③ 视觉：视觉圣经 + 地点资产 + 道具资产
  ↓
④ 分镜：正式镜头合同 + 连续镜头链
  ↓
⑤ 制作：一致性参考 → 快速画面候选 → 高质量精修 → 视频
  ↓
⑥ 成片：配音 + 字幕 + 背景音乐 + 最终合成
  ↓
最终 MP4
```

原工作台的六阶段页面、逐阶段修改、候选预览、丢弃和人工采用交互全部保留。生成成功不等于正式结果，只有用户明确采用的版本才进入下游生产。

## 前半段：一次理解，多次消费

### ① 故事生产圣经

作品前期建立统一事实源，沉淀不可篡改故事事实、世界观、时间线、剧情节点、人物关系、地点、关键道具、对白、旁白、连续性事件和创作节奏。后续角色、视觉和分镜阶段只读取自己需要的生产上下文切片，不再反复把完整故事交给模型重新理解。

### ② 角色资产与形象版本

角色是项目级版本资产，不只是文本描述。稳定身份包括脸部、发型、体型、肤色、常态服装、鞋履、固定配饰、主辅配色和身份锚点；剧情变化通过独立形象版本表达，例如默认造型、雪山造型、战斗破损造型和结局造型。

修改某个角色或某个形象版本，只让真实引用它的镜头和媒体结果过期。

### ③ 视觉资产

视觉阶段独立维护项目视觉圣经、地点空间结构、固定场景锚点、道具轮廓/材质/结构/纹样，以及天气、时段、破损等可变化状态。剧情“场次”只负责组织故事，不重复创建一套地点身份。

### ④ 正式分镜合同

每个正式镜头包含剧情节点、时长、人物及形象版本、地点和道具版本、景别、构图、机位、运镜、动作、表演、视线、环境、光线、对白、旁白、音效、音乐意图、静态代表状态、视频起止状态、图片生成要求、视频生成要求、连续镜头继承关系和智能质量等级。

同一地点、同一人物集合、同一形象版本且没有时间跳跃时，后一镜头可继承前一镜头结束状态；场景切换、时间跳跃、人物变化或形象变化会自动断链。

## 多参考一致性

用户可以上传参考图，也可以完全不上传。系统会为角色、地点和道具自动准备参考候选，只有人工采用后才成为正式一致性参考资产。

当前图片生产使用角色感知多参考工作流，单镜头最多绑定 4 个正式参考：

```text
人物参考 → FaceID 身份链
人物参考 → FaceID 身份链
地点参考 → 通用 IP-Adapter 链
道具参考 → 通用 IP-Adapter 链
                ↓
          同一冻结生成合同
```

系统会根据资产角色决定参考类型；人物不会再和场景/道具混用同一套身份注入方式。实际用了几张参考，就动态编译几路节点，未使用的槽位不会出现在执行图中。超过 Provider 参考预算时直接失败，不静默丢参考。

多角色同镜头仍以真实 AutoDL 输出做最终质量验收：代码层和工作流层已经支持多路人物/场景/道具参考，但是否达到发布标准以实际生成结果是否出现身份融合、错脸或参考丢失为准。

## 智能质量生产

镜头内部按内容价值分为 A / B / C 三档：

- **A**：主角身份、关键情绪特写、高潮、核心场景和核心道具
- **B**：常规剧情镜头
- **C**：过渡、建立、无人物或低风险环境镜头

页面只显示“智能质量”，系统决定实际生成预算。

图片采用两段式候选：

```text
正式镜头合同
  ↓
快速预览候选
  ↓
丢弃 / 重做 / 同种子高质量精修
  ↓
精修候选
  ↓
人工最终采用
```

普通“重新生成”会冻结新的真实 seed；“高质量精修”才继承预览 seed、提示词和正式参考资产，提高采样预算生成独立候选，不会后台覆盖原结果。

## 图片与视频生产

正式图片生成参数进入冻结 Generation Contract，包括实际宽高、画幅、steps、CFG、seed、sampler、scheduler 和正式参考资产版本。

视频必须从已采用首帧继续生成：

```text
已采用镜头画面
  ↓
正式首帧血缘
  ↓
H3 视频候选
  ↓
预览 / 丢弃 / 采用
```

视频不会绕过正式首帧重新猜开场画面。

## 全局作品资产与放大预览

生成结果不再只能在产生它的页面查看。

工作台提供全局“作品资产”入口，任意阶段都可以查看：

- 正式文本/结构化资产
- 角色、地点、道具资产
- 图片候选与已采用图片
- 视频候选与已采用视频
- 配音、字幕、背景音乐和成片
- V3 资源版本与生成来源

资产详情显示阶段、用途、版本、状态、逻辑键、实体绑定、上游资产、参考资产、生成来源和下游引用。

页面中已经显示出来的生成图片/视频也支持直接点击放大或全屏播放；文本/结构化结果可以在作品资产面板查看全文。这样文生图、镜头画面、参考图、视频和成片都能跨阶段追溯，而不是在各模块里重复堆一份副本。

## 内容哈希与增量复用

### 文本生产缓存

文本模型调用按照模型、专业 Skill、生产上下文、用户修改和执行目标计算内容签名。输入完全一致时直接复用已有结果，不重复调用模型。

### 媒体生产缓存

图片和视频除了 Temporal 单任务幂等外，还维护跨新任务的项目级媒体内容签名。

图片签名包含 Prompt、正式参考文件校验值、Provider/Workflow 指纹、宽高、steps、CFG、seed、sampler、scheduler 和质量阶段；视频签名包含视频 Prompt、已采用首尾帧文件校验值、H3 运行配置、宽高、长度、steps 和 seed。

签名完全一致且原媒体文件校验仍有效时，新任务直接复用已有不可变媒体文件，不重新提交昂贵生成任务，也不需要先切换 GPU 工作区。

## GPU 工作区策略

重型 GPU 服务互斥运行，但工作区不会在每个任务结束后自动关闭。同一类型连续任务继续复用当前已预热工作区。

```text
文本模型工作区
故事 → 角色 → 视觉 → 全部分镜和媒体要求

        ↓

图片工作区
批量缺失参考资产 → 镜头图片候选 → 精修候选

        ↓

视频工作区
已采用首帧 → 视频候选

        ↓

人物处理工作区
仅在确实需要人物处理时进入
```

命中媒体内容缓存时会在申请 GPU 工作区之前直接返回，避免无意义的模型切换。

## 确定性审计优先

能由规则准确判断的问题不额外调用大模型，例如必填字段、角色/地点/道具正式版本绑定、静态代表状态闭合、视频首帧来源、资源文件存在性、版本依赖、参考预算和连续镜头继承条件。只有规则无法判断的语义质量问题才进入更昂贵的语义审计。

## 后期并行生产

④正式分镜确认后，配音、字幕、背景音乐意图/曲库候选可以与⑤图片和视频生产并行准备。所有正式视频采用后，再把视频、配音、字幕和已采用背景音乐合成为最终成片。

背景音乐不会随机乱配：系统只把已经存在且可验证的用户曲库或默认曲作为候选，用户试听后采用；没有可用来源时明确提示上传或配置来源。

## 局部修改与依赖失效

平台维护真实资产版本和父子依赖关系。修改一个角色、地点、道具或单个镜头，只让真实依赖它的参考图、分镜、图片、视频和最终成片过期，无关内容继续有效。

## 工作台原则

1. **正式资产优先**：模型不得偷偷重写已确认人物、地点和道具身份。
2. **候选不等于正式结果**：所有关键媒体必须显式采用。
3. **局部修改只重算真实下游**：不做无意义的整项目重跑。
4. **视频首帧必须有来源**：只从已采用画面继续生成。
5. **参考不能静默丢失**：参考预算不足时显式失败。
6. **缓存必须可证明一致**：Prompt、参考文件、模型工作流或参数任一变化都会产生新签名。
7. **失败显式暴露**：缺能力、缺资产、合同不完整时不静默换链路。
8. **用户可见内容中文化**：内部稳定技术 ID 不直接当页面文案展示。
9. **测试与正式实现一致**：不维护只为测试通过的伪生产方案。

## 部署

默认目录：

```text
/root/autodl-tmp/ai-studio/platform-v2
```

安装：

```bash
cd /root/autodl-tmp/ai-studio/platform-v2
chmod +x scripts/*.sh
bash scripts/install.sh
```

启动：

```bash
bash scripts/start.sh
```

停止：

```bash
bash scripts/stop.sh
```

检查：

```bash
bash scripts/check.sh
```

AutoDL 对外映射 `6008` 即可。

## 更新当前开发分支

```bash
cd /root/autodl-tmp/ai-studio/platform-v2
git pull --ff-only origin refactor/xiaoduan-studio-v3
bash scripts/stop.sh
bash scripts/start.sh
```

更新页面后建议执行一次浏览器强制刷新。

## 发布前最终验证

代码层已经建立专业前半段生产 Skill、生产上下文切片、角色形象版本、角色/地点/道具版本资产、连续镜头继承、四路角色感知多参考、智能质量、两段式图片候选、文本与媒体内容哈希复用、参考图优先、视频首帧血缘、全局资产预览、配音/字幕/背景音乐并行准备和最终合成。

正式发布前仍以真实浏览器和真实媒体质量做最后验收，重点包括：

- 两个及以上人物同镜头时的身份独立性和错脸/融合情况
- 多镜头人物、场景和道具视觉一致性
- 长故事分批生产的剧情和分镜质量
- A/B/C 智能质量在真实 GPU 上的耗时与质量收益
- 从故事输入到最终 MP4 的浏览器完整回归

项目不把“接口成功”或“CI 通过”当成“视频质量已经优秀”；最终标准是实际生成出的连续、可看、可编辑、可稳定复现的视频成片。
